# Nginx and API Gateway Implementation

This guide adds the public request path:

```text
Client -> Nginx -> NestJS API Gateway -> one downstream service
```

Nginx is the edge proxy. It handles the public listener, request-size limits, buffering, TLS termination later, and load-balancing configuration. The NestJS gateway owns application routing, authentication, rate limits, correlation IDs, and forwarding to the correct service.

## 1. Repository topology

The current repository already reserves these local ports:

| Component | Local port | Gateway URL prefix |
|---|---:|---|
| Nginx | `80` | public entry point |
| API gateway | `3000` | `/api/...` |
| Identity service | `3001` | `/api/identity/...` |
| Vendor service | `3002` in the platform plan; `6060` in its current runtime config | `/api/vendor/...` |
| Vendor admin service | `3003` | `/api/vendor-admin/...` |
| Subscription service | `3004` | `/api/subscriptions/...` |
| Payment service | `3005` | `/api/payments/...` |
| Notification service | `3006` | `/api/notifications/...` |

## 2. Install Nginx

```bash

```

Nginx's main configuration is normally `/etc/nginx/nginx.conf`. Site configurations are normally stored in `/etc/nginx/sites-available` and enabled with a symlink in `/etc/nginx/sites-enabled`.

## 3. Create the Nginx reverse-proxy configuration

Create a site file:

```bash
sudo nano /etc/nginx/sites-available/vendor-backend
```

Use this local-development configuration:

```nginx
upstream vendor_api_gateway {
    # Add more gateway instances later without changing the public URL.
    server 127.0.0.1:3000;
    # server 127.0.0.1:3010;
}

server {
    listen 80;
    listen [::]:80;
    server_name _;

    client_max_body_size 10m;

    location = /nginx-health {
        access_log off;
        default_type text/plain;
        return 200 'ok\n';
    }

    # The gateway receives the complete /api/... URI.
    location /api/ {
        proxy_pass http://vendor_api_gateway;
        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host $host;

        proxy_connect_timeout 5s;
        proxy_send_timeout 30s;
        proxy_read_timeout 30s;
        proxy_buffering off;
    }

    # Keep gateway Swagger reachable during development.
    location /docs {
        proxy_pass http://vendor_api_gateway;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # Do not expose arbitrary gateway internals through Nginx.
    location / {
        return 404;
    }
}
```

Enable it and remove any stale/default site that still listens on port 80:

```bash
sudo ln -s /etc/nginx/sites-available/vendor-backend /etc/nginx/sites-enabled/vendor-backend
sudo rm -f /etc/nginx/sites-enabled/default /etc/nginx/sites-enabled/medixcel-base 2>/dev/null || true
sudo nginx -t
sudo systemctl reload nginx
```

If another legacy site is still enabled, remove it too; otherwise Nginx may keep serving the wrong `server` block and return `404` for `/nginx-health` even though your custom config is correct.

Important: `proxy_pass http://vendor_api_gateway;` has no URI suffix, so Nginx preserves `/api/...` when forwarding. This is what allows the Nest gateway to make the routing decision.

### Verify Nginx before the gateway exists

```bash

```

Expected response: HTTP `200` and `ok`.

## 6. Gateway implementation

Replace the starter controller/service with a registry-driven proxy. The gateway accepts a public prefix, selects one configured upstream, removes the gateway-only prefix, and forwards the remaining path.

### `src/service-registry.ts`

```ts
export type GatewayServiceName =
  | 'identity'
  | 'vendor'
  | 'vendorAdmin'
  | 'subscription'
  | 'payment'
  | 'notification'
  | 'activity';

export type GatewayService = {
  name: GatewayServiceName;
  publicPrefix: string;
  baseUrl: string;
};

export const serviceRegistry: GatewayService[] = [
  {
    name: 'identity',
    publicPrefix: '/api/identity',
    baseUrl: process.env.IDENTITY_SERVICE_URL ?? 'http://127.0.0.1:3001',
  },
  {
    name: 'vendor',
    publicPrefix: '/api/vendor',
    baseUrl: process.env.VENDOR_SERVICE_URL ?? 'http://127.0.0.1:6060',
  },
  {
    name: 'vendorAdmin',
    publicPrefix: '/api/vendor-admin',
    baseUrl:
      process.env.VENDOR_ADMIN_SERVICE_URL ?? 'http://127.0.0.1:3003',
  },
  {
    name: 'subscription',
    publicPrefix: '/api/subscriptions',
    baseUrl:
      process.env.SUBSCRIPTION_SERVICE_URL ?? 'http://127.0.0.1:3004',
  },
  {
    name: 'payment',
    publicPrefix: '/api/payments',
    baseUrl: process.env.PAYMENT_SERVICE_URL ?? 'http://127.0.0.1:3005',
  },
  {
    name: 'notification',
    publicPrefix: '/api/notifications',
    baseUrl:
      process.env.NOTIFICATION_SERVICE_URL ?? 'http://127.0.0.1:3006',
  },
  {
    name: 'activity',
    publicPrefix: '/api/activity',
    baseUrl: process.env.ACTIVITY_SERVICE_URL ?? 'http://127.0.0.1:3007',
  },
];

export function findService(path: string): GatewayService | undefined {
  return serviceRegistry.find(
    (service) =>
      path === service.publicPrefix ||
      path.startsWith(`${service.publicPrefix}/`),
  );
}
```

### `src/proxy.service.ts`

```ts
import {
  BadGatewayException,
  GatewayTimeoutException,
  Injectable,
  NotFoundException,
} from '@nestjs/common';
import axios, { AxiosRequestConfig, AxiosResponse } from 'axios';
import { findService } from './service-registry';

@Injectable()
export class ProxyService {
  async forward(
    method: string,
    requestPath: string,
    query: Record<string, unknown>,
    body: unknown,
    headers: Record<string, string | string[] | undefined>,
    requestId: string,
  ): Promise<AxiosResponse> {
    const service = findService(requestPath);

    if (!service) {
      throw new NotFoundException('No gateway route matches this request');
    }

    const downstreamPath = requestPath.slice(service.publicPrefix.length) || '/';
    const url = new URL(downstreamPath, `${service.baseUrl.replace(/\/$/, '')}/`);

    Object.entries(query).forEach(([key, value]) => {
      if (value !== undefined) {
        url.searchParams.set(key, String(value));
      }
    });

    const forwardedHeaders: Record<string, string> = {};
    for (const [key, value] of Object.entries(headers)) {
      const lowerKey = key.toLowerCase();
      if (
        value !== undefined &&
        !['host', 'content-length', 'connection'].includes(lowerKey)
      ) {
        forwardedHeaders[key] = Array.isArray(value) ? value.join(',') : value;
      }
    }

    forwardedHeaders['x-request-id'] = requestId;
    forwardedHeaders['x-gateway-service'] = service.name;

    const config: AxiosRequestConfig = {
      method,
      url: url.toString(),
      headers: forwardedHeaders,
      data: body,
      timeout: Number(process.env.PROXY_TIMEOUT_MS ?? 10000),
      validateStatus: () => true,
      maxContentLength: 10 * 1024 * 1024,
      maxBodyLength: 10 * 1024 * 1024,
    };

    try {
      return await axios.request(config);
    } catch (error) {
      if (axios.isAxiosError(error) && error.code === 'ECONNABORTED') {
        throw new GatewayTimeoutException('Downstream service timed out');
      }
      throw new BadGatewayException('Downstream service is unavailable');
    }
  }
}
```

### `src/proxy.controller.ts`

```ts
import {
  All,
  Controller,
  Headers,
  Param,
  Query,
  Req,
  Res,
} from '@nestjs/common';
import { Request, Response } from 'express';
import { randomUUID } from 'node:crypto';
import { ProxyService } from './proxy.service';

@Controller()
export class ProxyController {
  constructor(private readonly proxyService: ProxyService) {}

  @All('*path')
  async proxy(
    @Param('path') path: string | string[],
    @Req() request: Request,
    @Res() response: Response,
    @Headers() headers: Record<string, string | string[] | undefined>,
    @Query() query: Record<string, unknown>,
  ): Promise<void> {
    const routePath = `/${Array.isArray(path) ? path.join('/') : path}`;
    const requestId =
      request.header('x-request-id')?.trim() || randomUUID();

    const downstream = await this.proxyService.forward(
      request.method,
      routePath,
      query,
      request.body,
      headers,
      requestId,
    );

    response.setHeader('x-request-id', requestId);
    for (const [key, value] of Object.entries(downstream.headers)) {
      if (!['connection', 'transfer-encoding'].includes(key.toLowerCase())) {
        response.setHeader(key, value);
      }
    }
    response.status(downstream.status).send(downstream.data);
  }
}
```

The `@All('*path')` route is intentionally last-resort routing. Add explicit gateway controllers for routes that need gateway-owned validation, authentication guards, response aggregation, or special file/stream handling.

## 7. How a request is routed

Example request:

```text
GET /api/payments/intents?orderId=123
```

1. Nginx receives the request on port `80`.
2. Nginx forwards the unchanged URI to `http://127.0.0.1:3000/api/payments/intents`.
3. The gateway finds the `/api/payments` registry entry.
4. The gateway strips only `/api/payments`.
5. The payment service receives `GET /intents?orderId=123`.
6. The gateway copies the downstream status/body back to the client and returns `x-request-id`.

For the current vendor service, use an explicit mapping because its existing routes include `/admin/api`:

```text
Public:    /api/vendor/admin/api/product/select-product
Gateway:   strips /api/vendor
Downstream: /admin/api/product/select-product
```

If you prefer the public URL to be `/admin/api/...`, add a separate registry entry or an explicit controller instead of guessing a rewrite rule.

## 9. Security requirements before production

- Do not trust client-provided `x-user-id`, `x-role`, or similar identity headers. Strip them and set them only after JWT verification.
- Add JWT verification for protected route groups using the identity service JWKS endpoint.
- Add a Redis-backed rate limiter before running multiple gateway replicas. In-memory limits are not shared between instances.
- Keep service ports private; clients should reach only Nginx.
- Set a real `server_name`, TLS certificates, security headers, and a restrictive CORS allow-list.
- Add body-size and timeout limits appropriate to each route. File uploads may need a dedicated streaming proxy path.
- Add circuit breakers and health checks around downstream calls. A timeout prevents one unavailable service from consuming all gateway resources, but it is not a complete circuit breaker.
- Add request IDs to logs in Nginx, the gateway, and every downstream service.

## 10. Adding another service

1. Start the service on a private port.
2. Add its URL to `.env` and `.env.example`.
3. Add one entry to `src/service-registry.ts`.
4. Define the downstream route contract and authentication requirement.
5. Add a focused gateway test for the path and forwarded method/query/body.
6. Run `npm run build` and test through both `127.0.0.1:3000` and Nginx.

Nginx should not need a new location for every business service. It forwards the public API namespace to the gateway; the gateway owns service selection.
